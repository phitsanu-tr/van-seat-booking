# VanTrip (van-seat-booking)

เว็บจองที่นั่งรถตู้ (คันละ 10 ที่นั่ง) ผู้จัดสร้างทริปแล้วแชร์ลิงก์ เพื่อนเข้าด้วย LINE แล้วแตะเลือกที่นั่งเอง ใช้ผ่าน LINE (LIFF) หรือเบราว์เซอร์ทั่วไปได้ · มีโหมด "จองตามลำดับคิว" และแจ้งเตือนทางแชต LINE

เว็บจริง: https://van-seat-booking.vercel.app/ · โฮสต์บน Vercel · เก็บข้อมูลใน Upstash Redis · ไม่มีขั้นตอน build

## ติดตั้งบน Vercel

1. vercel.com → Add New → Project → import repo นี้ · Framework Preset = **Other** · Build Command ว่างไว้
2. Storage → เพิ่ม **Upstash for Redis** แล้วเชื่อมเข้าโปรเจกต์ (ระบบใส่ `KV_REST_API_URL` / `KV_REST_API_TOKEN` ให้ อ่านได้แม้มี prefix เช่น `VAN_SEAT_BOOKING_`)
3. Environment Variables (Production):
   - `LINE_CHANNEL_ID`, `LINE_CHANNEL_SECRET` (จาก LINE Developers → LINE Login channel)
   - ไม่บังคับ: `LINE_REDIRECT_URI` (ถ้าไม่ใส่ใช้ `https://<โดเมน>/api/auth`), `OWNER_KEY` (ยาว 16 ตัวขึ้นไป สำหรับหน้า `/owner`)
   - ไม่บังคับ (ปิดไว้ถ้าไม่ตั้ง):

     | ตัวแปร | ผล |
     |---|---|
     | `LINE_BOT_TOKEN` | Channel access token (long-lived) ของ Messaging API ของ OA "Van Trip" → ส่งแจ้งเตือนสำคัญเข้าแชต LINE ด้วย |
     | `REQUIRE_OA_FRIEND=1` | ผู้โดยสารต้องเพิ่ม OA "Van Trip" เป็นเพื่อนก่อนใช้งาน (`OA_ADD_URL` = ลิงก์เพิ่มเพื่อน ถ้าไม่ใส่ใช้ `https://line.me/R/ti/p/@976dllrx`) |

## จองตามลำดับคิว (`PAYMENT_QUEUE=1`)

ใช้เมื่ออยากให้คนที่จ่ายเงินก่อนได้เลือกที่นั่งก่อน ผู้จัดเปิดจากเมนู "⋯" ของการ์ดทริป → "คิวจองตามลำดับ" (`/<รหัส>/queue`)

**ผู้จัด**
- การ์ดสวิตช์ด้านบน: "เปิดระบบคิว" (พื้นเขียว) / "ปิดระบบคิว" (พื้นเทา) บรรทัดรองบอกว่าถึงคิวใคร · มีคนรออนุมัติ = แถบเหลืองพร้อมปุ่ม "อนุมัติ"
- แท็บรายชื่อ: เพิ่มชื่อทีละหลายคน (ชีตเลื่อนขึ้นจากด้านล่าง บรรทัดละ 1 คน มีเลขลำดับคิวที่จะได้) · เมนู "⋯" ต่อชื่อ: เลื่อนขึ้น/ลง, ปลดชื่อ, ข้าม/จบคิว, ลบ
- จำนวนชื่อสูงสุด = ที่นั่งรวมทุกคัน (คันละ 10, เพดาน 80) แสดงเป็น "8 / 10 คน"
- แท็บตั้งค่า: ยืนยันชื่อผู้โดยสารแบบ "ผู้จัดอนุมัติเอง" (แนะนำ) หรือ "อนุมัติอัตโนมัติ"
- ผู้จัดและผู้ช่วยจองได้เสมอ ไม่ต้องรอคิว · ปุ่มล่าง "ย้อนกลับ" กลับไปหน้าที่มา

**ผู้โดยสาร**
- ก่อนเข้าคิว: เห็นรายชื่อเพื่อหาชื่อตัวเองแล้วกด "ฉันคือคนนี้" (โหมดอัตโนมัติมีชีตยืนยัน "คุณคือ … ใช่ไหม" ก่อน 1 ครั้ง)
- หลังเข้าคิว: เห็นเฉพาะสถานะของตัวเอง (อีก N คน / ถึงคิวแล้ว / รออนุมัติ / ใช้สิทธิ์แล้ว) และปุ่ม "ไม่ใช่ฉัน" · เซิร์ฟเวอร์ไม่ส่งชื่อคนอื่นมาให้แล้ว
- ในผังที่นั่ง: ยังไม่ถึงคิวแตะที่นั่งว่าง = ชีต "ยังไม่ถึงคิวคุณ" (ตัวเลขใหญ่ "อีก N คน" + จุดคิวไม่ระบุชื่อ) อัปเดตเอง พอถึงคิวเปลี่ยนเป็นปุ่ม "เลือกที่นั่ง N" · ยังไม่ได้เพิ่มเพื่อน OA = แถบเตือนพร้อมปุ่มเพิ่มเพื่อน
- ถึงคิว: จองครบจำนวนต่อคน (หรือกด "จองเสร็จแล้ว") แล้วคิวไปคนถัดไปเอง และคนถัดไปได้แจ้งเตือน

**ยกเลิกที่นั่งตอนเปิดคิว**
- ผู้โดยสารยกเลิกเองไม่ได้ (API ตอบ 403 `ask_organizer`) → กด "ขอยกเลิกที่นั่ง" เลือกเหตุผลได้ (ไม่บังคับ) · ระหว่างรอ ที่นั่งเป็นสีเหลือง "รอยกเลิก" และถอนคำขอได้
- ทีมผู้จัดได้แจ้งเตือน "… ขอยกเลิกที่นั่ง N" กด "อนุมัติยกเลิก" / "ไม่อนุมัติ" ได้ในแจ้งเตือน หรือแตะที่นั่งนั้นในผัง · ผู้โดยสารได้แจ้งผลกลับ
- ปิดคิว: ยกเลิกเองได้ตามปกติ

## แจ้งเตือนทาง LINE (`LINE_BOT_TOKEN`)

ส่งจาก OA "Van Trip" ซ้ำกับแจ้งเตือนในแอป เฉพาะเรื่องสำคัญ (นับโควตาข้อความของ OA): ถึงคิวจอง, ทริปเปลี่ยน/ถูกยกเลิก, ที่นั่งถูกย้าย/ยกเลิก, คันรถถูกลบ, คำขอยกเลิกที่นั่ง (ถึงทีมผู้จัด) และผลคำขอ (ถึงผู้โดยสาร) · ไม่ส่งหาคนที่เป็นคนทำเรื่องนั้นเอง · ผู้รับต้องเป็นเพื่อนกับ OA · ส่งไม่ผ่านดูได้ใน Vercel Logs (`[line push] status …`: 401 = token ผิด, 429 = โควตาหมด)

**ความถูกต้องเมื่อกดพร้อมกัน**
- จองที่นั่งเดียวกันพร้อมกัน ได้คนแรกคนเดียว (`HSETNX`)
- ติ๊กขึ้นรถ แก้ชื่อ ย้าย/สลับ และเริ่มรอบเช็กชื่อใหม่ เขียนแบบตรวจก่อนเขียนในคำสั่งเดียว (Lua `hcas` ใน `api/_lib.js`) ที่นั่งที่ถูกยกเลิกระหว่างนั้นจะไม่กลับมา และการย้ายไม่ค้างครึ่งทาง

**จำกัดความถี่**
- จอง/ยกเลิก/แก้ 30 ครั้งต่อ 10 นาทีต่อคนต่อทริป (ติ๊กขึ้นรถแยกโควตา 400 ครั้ง) · สร้างทริป 30 ทริปต่อเดือนต่อบัญชี

| `inbox:<บัญชี>` (+ `inboxr` `inboxa` `inboxv`) | การแจ้งเตือน 50 รายการ เก็บ 60 วัน |
| `rl:*`, `hold:*`, `mark:*` | ตัวนับจำกัดความถี่, การกันที่นั่งชั่วคราว, รหัสไฮไลต์บัตรที่นั่ง (ทั้งหมดหมดอายุเอง) |

ข้อมูลทริป (ทริป ที่นั่ง ประวัติ) หมดอายุเอง 60 วันหลังวันสุดท้ายของทริป (สิ้นวันเวลาไทย; ตั้งที่ `RETENTION_DAYS`) · ทริปที่ไม่มีวันที่ไม่หมดอายุ (ลบได้ที่ `/mytrips` หรือ `/owner`)

## แพ็กเกจและการชำระเงิน

คนจัดทริปเป็นคนจ่าย ผู้จองที่นั่งใช้ฟรีเสมอ (`api/_plans.js`, `api/pay.js`, หน้า `/plans`)

| ราคาเปิดตัว (ถึง 5 ก.พ. 2570) | 0 | 99฿ · 990฿/ปี | 299฿ · 2,990฿/ปี | 29฿ |
| สร้างทริปต่อเดือน | 2 | 20 | ไม่จำกัด (เพดาน 100) | ไม่นับรวม |
| รถต่อทริป | 1 | 5 | 10 | 5 |
| ผู้ช่วยจัด | 0 | 2 | 5 | 2 |
| เช็กชื่อขึ้นรถ | 1 รอบ | ไม่จำกัด | ไม่จำกัด | ไม่จำกัด |

- ทุกอย่างเป็นการจ่ายครั้งเดียว (PromptPay ตัดเงินอัตโนมัติไม่ได้) ซื้อซ้ำ = ต่อเวลา, ใกล้หมดอายุ 3 วันมีแจ้งเตือนในกระดิ่ง
- สิทธิ์ของทริปตามแพ็กเกจของ **เจ้าของทริป** ผู้ช่วยใช้สิทธิ์ของเจ้าของ
- นับทริปตามเดือน (`quota:<YYYY-MM>:u:<uid>`) ลบทริปหรือ "ลบข้อมูลของฉัน" ไม่คืนโควตา ยกเว้นทริปที่ลบภายใน 24 ชม. หลังสร้างและยังไม่มีใครจอง
- บัญชีที่มีทริปอยู่แล้วตอนเปิดขาย ได้ Standard ฟรี 90 วัน (ครั้งเดียว)
- ชำระผ่าน Stripe Checkout (PromptPay หรือบัตร) ลูกค้าเห็นผู้รับเงินเป็น STRIPE PAYMENTS (THAILAND) LTD ไม่ใช่บัญชีส่วนตัว
- หน้า `/owner` มีรายรับ รายการซื้อ และให้สิทธิ์ด้วยมือ (ใส่รหัสทริป → ให้สิทธิ์เจ้าของทริปนั้น)

ตั้งค่าบน Vercel:

| ตัวแปร | ค่า |
|---|---|
| `PLANS_ON` | ไม่ต้องตั้ง = เปิดขาย · `0` = ปิดแพ็กเกจ (ยังเปิดให้บัญชีทดสอบจากหน้า /owner ได้) |
| `STRIPE_SECRET_KEY` | `sk_test_...` หรือ `sk_live_...` จาก Stripe Dashboard → Developers → API keys |
| `STRIPE_WEBHOOK_SECRET` | `whsec_...` จาก webhook ที่ชี้ไป `https://<โดเมน>/api/pay?hook=1` เลือก event `checkout.session.completed`, `checkout.session.async_payment_succeeded` และ `charge.refunded` (คืนเงินเต็มจำนวนใน Stripe → ยกเลิกสิทธิ์ของรายการนั้นเอง) |

ใน Stripe Dashboard ต้องเปิด PromptPay ที่ Settings → Payment methods ด้วย · ในเครื่อง (dev.js) ไม่ต้องมี Stripe: หน้าชำระเงินมีปุ่ม "จำลองว่าจ่ายแล้ว" · ชุดเทสเดิมรันโดยปิดแพ็กเกจ (`PLANS_ON=0`)

## ความปลอดภัย

- LINE Login: ใน LINE ใช้ LIFF (ส่ง ID token ให้เซิร์ฟเวอร์ตรวจกับ LINE) · นอก LINE ใช้แบบเว็บ ตรวจ state/nonce · ขอแค่ `openid profile` · คุกกี้ `HttpOnly; Secure; SameSite=Lax`
- รหัสบัญชี LINE ไม่ถูกส่งให้ผู้จองคนอื่น · เวลาขึ้นรถและรอบเช็กชื่อเห็นเฉพาะทีมผู้จัด · คิวจอง: ผู้โดยสารที่เข้าคิวแล้ว (หรือยังไม่ล็อกอิน) ไม่ได้รับชื่อคนอื่นจาก API
- Header: `X-Frame-Options: DENY`, `frame-ancestors 'none'`, `nosniff` ทุกหน้า · ให้ Google เก็บแค่หน้าแรกกับ `/privacy` (หน้าอื่นและ `/api` เป็น `noindex, nofollow` + `robots.txt`) · ชื่อจองห้ามใช้คำสงวน (admin, staff, คนขับ ฯลฯ)
- หน้า `/owner` ต้องมี `OWNER_KEY` (ไม่ตั้ง = API ตอบ 404) เปิดด้วย `/owner#คีย์` แล้วคีย์ถูกลบออกจากแถบ URL ทันที

## UI standard
- All font sizes and picture sizes are **even px** (22, 24, 26, 28 …). See `ui.css`.
- Page header (booking, create / edit trip): 4px teal bar on the left (stretches to the full height of the two text lines, so it always matches the text), then the title and one short line. Title / line sizes step with the screen width: 28/16 (≥414px), 26/14, 24/14, 22/12 (≤340px); the short line never wraps. Styles live in `ui.css`.
- Bottom menu: the 5-tab bar is in the app itself (`/home`, `/trips`, `/seats`, `/notify`, `/profile`) and, for signed-in users, on the trips form, plans, privacy and booking pages through `tabbar.js` (`data-tab` marks the active tab; keep its look in sync with the bar in `app.html`). The trips form asks before leaving when there is unsaved input.
- Top bar on every page: back arrow (sub-pages) · app name · bell.
